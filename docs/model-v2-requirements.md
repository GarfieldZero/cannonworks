# 大炮模型 v2 需求文档（重炮主题）

> 用途：本文件用于在新对话中启动「大炮外观建模」任务。实现者请先读完再动手。
>
> 实现记录（2026-10-25）：见 [`cannon-v3-implementation.md`](cannon-v3-implementation.md)（放大版 + 炮弹 + 开火表现；v2 文档保留为历史）。

## 1. 目标

把现有的「底座 + 一根方管」占位模型，升级成一座有辨识度的**重炮**：

- 一眼能看出是「炮」，不是「带管子的箱子」；
- 有重炮的味道：黑铁、铆钉、粗壮、工业感、带一点赤红符文装饰；
- 保持方块像素风格（不追求写实），与 Minecraft 原版比例协调。

## 2. 现状（必须先看）

| 文件 | 作用 |
| --- | --- |
| `src/main/java/com/cannonworks/client/CannonModel.java` | 程序化模型：`base` + `barrel`（`ModelPart` 层级） |
| `src/main/java/com/cannonworks/client/CannonRenderer.java` | `BlockEntityRenderer`：用 PoseStack 处理朝向与俯仰 |
| `src/main/resources/assets/cannonworks/textures/entity/cannon.png` | 128×64 贴图 |
| `src/main/java/com/cannonworks/block/CannonBlock.java` | 方块，含 `FACING` 朝向 |

当前实现要点：

- 模型是**纯代码构建**的（`CubeListBuilder` / `PartDefinition`），没有 Blockbench 工程文件；
- 模型坐标：1 单位 = 1/16 方块；
- 朝向由渲染器旋转 PoseStack（yaw 180°，随 `FACING`），**不要**把朝向烘进模型；
- 俯仰由 `barrel.xRot` 控制，枢轴在炮管尾部；
- 方块本身是完整 1×1，没有 `getShape` 的精细碰撞箱。

## 3. 硬性技术约束

1. **禁止引入外部模型文件**（`.json` 的 `geo`/`.bbmodel`）与第三方渲染库；只用原版 `ModelPart` + `CubeListBuilder`。
2. **禁止新增依赖**，不要改 `build.gradle`。
3. 贴图必须是 **2 的幂尺寸**，建议 128×128（预算上限 256×256），PNG 无外部引用。
4. 模型整体尺寸必须落在 **1×1×1 方块**内（允许视觉上略超出 ±0.05，但碰撞箱仍是整块）。
5. 不能影响服务端：模型/渲染类只能是 `Dist.CLIENT`。
6. 单个方块的渲染顶点数控制在合理范围（参考：现有模型 ~10 个立方体；上限 ~40 个立方体）。

## 4. 需要建模的部件

建议的层级（可微调，但语义要对）：

```
root
├─ base            底座/炮架（固定，不随俯仰）
│   ├─ carriage    两侧炮架板、支撑臂
│   ├─ wheels      轮子（左右各一，可选）
│   └─ details     铆钉、铭牌、锁链等装饰
└─ barrel          炮管（俯仰时绕尾部枢轴旋转）
    ├─ tube        炮管主体
    ├─ muzzle      炮口加粗段
    ├─ breech      尾部闭锁/药室
    └─ trim        箍环、瞄准具
```

要求：

- `barrel` 的枢轴必须在**炮管尾部**（俯仰时不穿模）；
- 炮管默认朝 **+Z**（南），与现有渲染器约定一致；
- 底座要能包住炮管尾部，俯仰到 5° 和 85° 时都不出现明显穿模；
- 轮子/支撑腿可选，但要有「能把后坐力撑住」的视觉重量感。

## 5. 美术方向

- **主色**：黑铁 `#2B2B30`、深灰 `#3C3C42`、旧钢 `#5A5A62`；
- **点缀**：赤红符文 `#B3261E` / `#E04B3A`（少量，工业能量纹路风格）；
- **辅色**：暗木 `#4A3626`（炮架/把手），黄铜 `#8C6B2F`（箍环、铆钉高光）；
- 表面要有**分层明暗**：顶面亮、侧面中、底面暗，避免大块纯色；
- 允许 1px 的磨损/掉漆噪点，但不要脏到看不清轮廓；
- 不要发光材质（不做 emissive），需要时用粒子表现。

## 6. 动画与特效（可选，优先级低于模型本体）

1. **后坐**：开火时 `barrel` 沿 -Z 回弹 1~2 格（1/16 方块单位）再回位，约 8 tick；
2. **炮口焰**：开火瞬间在炮口位置生成短命粒子（`ParticleTypes.FLAME` + `SMOKE`），不需要自定义粒子类型；
3. **装填指示**：可选，用模型上一个小的「药包」立方体随装药量显隐。

以上动画必须由**方块实体状态**驱动（现有 `fire()` 里已有触发点），不能在渲染器里读客户端随机数。

## 7. 衔接要求（不要破坏已有功能）

- 保留 `CannonRenderer` 的 `getRenderBoundingBox`、朝向与俯仰逻辑；
- GUI（`CannonScreen`）与物品图标不要求跟随新模型，但**物品图标要能看出是炮**（可另画 16×16 图标，不在本任务强制范围）；
- 模型改动不得影响：滑条俯仰角、射击数值、Waystone 联动。

## 8. 验收标准

实现完成后逐条自查：

- [ ] 游戏内放置大炮，四个朝向都能正确显示（炮口朝玩家面向的方向）；
- [ ] 俯仰从 5° 拖到 85°，炮管平滑旋转、与底座不穿插；
- [ ] 开火时能看到后坐（若实现了）与炮口焰；
- [ ] 贴图为 2 的幂，文件大小 < 200 KB；
- [ ] 没有新增依赖、没有客户端类泄漏到服务端；
- [ ] 模型在 1×1×1 内，方块碰撞与破坏逻辑不受影响；
- [ ] 截一张图放在 `docs/` 下（可选）。

## 9. 交付物

1. 改写后的 `CannonModel.java`（含部件层级与 UV）；
2. 新的 `cannon.png`（或其他同名贴图）；
3. 必要的 `CannonRenderer.java` 调整（枢轴、后坐、炮口位置常量）；
4. 在 `docs/` 下补一段简短的实现说明（部件尺寸表 + 贴图 UV 布局）。

## 10. 备注

- 这是**外观升级**，不改变任何数值逻辑；如果为了模型需要微调尺寸常量，请在文档里记录。
- 建模时优先保证「俯仰不穿模」和「四向正确」，这两点比细节更重要。
- 如果时间有限，先交付「底座 + 炮管 + 炮口」三段式，装饰件可以后续迭代。
