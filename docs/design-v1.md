# Cannon Works 设计草案 v1

> 目标：**不用跑图，也能把「传送石碑」或「人」投送到没去过的坐标。**
> 玩法骨架参考《铁巢重炮》：测距 → 定方位 → 算装药 → 调俯仰 → 点火 → 观察飞行 → 落地生效。

---

## 1. 核心循环

```
侦察（地图/坐标） → 架炮 → 装药 + 装负载 → 定方位/俯仰（或交给火控计算机）
      → 点火 → 炮弹飞行 10~30s（服务端逐 tick 推进，只加载自身所在区块）
      → 落地：弹坑 + 负载生效（石碑落地自动激活 / 玩家安全着陆 / 货物完整）
```

## 3. 弹道模型（S1 的核心）

### 3.1 为什么不用「真实重力」

真实抛物线里 **顶点高度 ≈ 射程 × tanθ / 4**：45° 打 1000 格顶点就要 250 格，60° 要 430 格——
超过世界高度、也完全不像「缓慢飞过去」。所以采用**设计者可调的参数化弹道**，物理只作为手感参考。

### 3.2 参数

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `R` | 水平射程（格） | 由装药反解，上限 1500 |
| `θ` | 俯仰角 | 5°–85° |
| `A` | 弹道顶点高度 | `clamp(R·tanθ/4, 10, 300)` |
| `V` | 平均飞行速度 | 50 格/秒（可配） |
| `T` | 飞行时间 | `R/V × (1 + 0.5·sinθ)` |

1000 格、45° → 顶点约 250、飞行约 27 秒；15° 低抛 → 顶点 67、约 22 秒。
→ **高低抛的差别不是「另一个公式」，而是同一个公式下顶点不同**：低抛更容易被山挡住，高抛能越过。

### 3.3 轨迹

以水平距离比例 `u ∈ [0,1]` 参数化（`Δy` = 目标与炮口高差）：

```
h(u) = Δy · u + 4A · u · (1 - u)
pos(u) = origin + dir · (R · u) + up · h(u)
```

- 每 tick 推进 `Δt`，`u += (Δt / T)`，在 `[u_prev, u]` 区间内**按 ≤1 格步长采样**做 `level.clip(...)` 碰撞。
- 命中方块/实体 → 就地引爆（低抛被山拦截就是这里发生）。
- 炮口前 3 tick 忽略碰撞，避免打到自己。

### 3.4 反解（给火控计算机）

给定目标 `(dx, dy, dz)`：`R = √(dx²+dz²)`，`yaw = atan2(dz, dx)·180/π - 90`。
装药量按射程表 `R(charge)` 单调反解；`θ` 由玩家选（低抛/高抛），或默认取「能越过沿途最高地形的最小 θ」。

### 3.5 极限射程与高度（10km 级）

**射程**：`MAX_RANGE = 12000`、`MAX_APEX = 3000`。10000 格 45° → 顶点 2500 格、飞行 270.7 秒。
实测落点 `10000.5 / -60.0 / 0.5`，5414 tick，分毫不差。

**高度**：方块只到 y=319，但**实体没有高度上限**。炮弹能飞到 y=2500；
320 以上那一段没有任何方块，射线检测必然 miss —— 所以「高抛越过一切」不是特判，是几何结果。
代价：那一段玩家完全看不见（也没有地形可看），只能靠 HUD / 地图。

**10km 一发要穿过 625 个区块列**，边飞边生成：

| 指标 | 空载 | 10km 飞行中 |
| --- | --- | --- |
| 平均 tick | 0.276 ms | 0.765 ms |
| TPS | 20.000 | 20.000 |

平坦世界几乎无感；真实地形（山地/海洋/结构）会明显更贵，而且会**永久生成**你从没去过的地形（存档膨胀）。
所以 `MAX_RANGE` 必须是服务端可配项。

**长射程的时间取舍**：按「1000 格 ≈ 20 秒」线性放大，10000 格就是 4.5 分钟。
可配 `blocksPerSecond`（默认 50）；另一种选择是**巡航段加速**（前 10% 慢、中段快、末段慢），观感更好，待定。

### 3.6 被地形拦截

逐 tick 射线命中方块，就在**命中点**落地（不是飞到目标才落地）。
实测：在 x=50 处砌一堵 15 格高的墙，5° 低抛打 1000 格 → `impact at 50.0/-54.4/0.0 (hit BLOCK) after 21 ticks`。

- 发射者会收到「炮弹被地形拦截于 X, Y, Z（负载在此处落点）」。
- 设计选择（M2 定）：拦截点默认**完整触发落点效果**（弹坑 + 放碑）；可配 `payloadOnIntercept=false` 变成哑弹。
- 低抛 10km 时，被挡大概率发生在**出膛后头几公里**（顶点 2500 是中段才到），所以后续要加**出膛弹道净空检查**。

## 4. 飞行与区块加载（S1/S7）

### 4.1 用「短寿命 ticket」而不是强制加载

1.20.1 里可以自建 `TicketType`：

```java
TicketType<ChunkPos> SHELL = TicketType.create("cannonworks:shell",
        Comparator.comparingLong(ChunkPos::toLong), 40); // 40 tick 后自动过期
```

每 tick 给炮弹所在区块 `addRegionTicket(SHELL, chunkPos, radius, chunkPos)`，
**不需要手动清理**——过期即释放。方案可配：

| 模式 | 说明 | 成本 |
| --- | --- | --- |
| `SHELL_ONLY`（默认） | 只加载炮弹所在 1 个区块 | 极低，约 2–3 区块/秒 |
| `RADIUS_1` | 3×3 区块 | 低，适合需要精确看地形的弹道 |
| `NONE` | 不加载（炮弹在未加载区会「冻结」） | 仅调试用 |

### 4.2 ⚠️ 一个必须说清的误区

**服务端加载区块 ≠ 玩家能看见那片地形。**
区块只发给视距内的玩家；炮弹在 800 格外加载的区块，站在炮位的玩家依然看不到地形，
最多在地图上看到一个点。想「看着炮弹飞过去」，需要额外的**观测镜/跟随镜头**（会主动给客户端发远处区块，成本高），建议放到 M5 做成可选道具。

### 4.3 性能

- 1000 格飞行 ≈ 63 个区块列，分摊到 20 秒 ≈ 3 列/秒，和玩家正常跑图同量级。
- 10km ≈ 625 个区块列，分摊到 270 秒 ≈ 2.3 列/秒；实测 tick 0.765ms、TPS 全程 20。
- 真正的成本是**地形生成**（新区块），不是 ticket 本身；首飞穿越未探索区域会有一次性的生成开销。
- 多炮弹并发：默认限制同时 8 发，超出排队。

## 5. 落点（S3）

### 5.1 弹坑

- **几何原则：以命中点为中心的三维球，不是投影到高度图的圆。**
  打在山壁上就在山壁上炸洞，洞底就是洞里的地面，**绝不会把效果平移到山脚**。
- 球心沿来向往材质里推 0.5 格，保证坑有一半嵌在材质里。
- 半径由装药决定（默认 2–6 格），单发上限 512 个方块。
- 跳过：基岩/屏障（硬度 < 0）、容器方块实体（防刷）、空气、世界外。
- 被炸掉的方块**默认不掉落**（`craterDrops=false`），避免「打一发收一背包」。

实测（在 x=50 砌一堵 15 格高的墙，5° 低抛命中）：

| 位置 | 结果 |
| --- | --- |
| 命中高度 50/-54/0 | 空（打穿了） |
| 坑底 50/-56/0 | 空 |
| 墙顶 50/-45/0 | 完好 |
| 墙外 50/-48/0 | 完好 |
| **墙脚地面 50/-59/0** | **完好**（没有塌到墙脚） |

- **薄墙例外**：1–2 格厚的墙会被整个打穿，炮弹相当于穿过去在地面炸开——这是合理的物理表现。
  若要让薄墙也能挡住，需改成「朝材质内部的半球 + 穿透判定」（M2 可选）。

### 5.2 两个独立栏位：缓冲物 / 填充物（互斥）

炮弹有**两个互斥**的落点栏位：

| 栏位 | 装什么 | 落点效果 |
| --- | --- | --- |
| **缓冲物** | 草垛 | 无弹坑、无破坏；落点**正下方一格**替换成草垛，货物/玩家轻着陆 |
| **缓冲物** | 水桶 | 无弹坑；水放在落点**旁边**（放正下方会被货物方块挤掉） |
| **填充物** | 石头/泥土/黑曜石… | 有弹坑；填充方块**零散出现在弹坑内壁/底部** —— 这就是「空投建材」 |
| 空 | — | 纯弹坑 |

- 两栏互斥（GUI 只能装一种）：**缓冲 = 软投送**（人、精密货物），**填充 = 硬投送**（建材、爆破）。
- 传送石碑这类「特殊负载」放第三个槽位，不占缓冲/填充。

防刷三条硬规则：① 负载在点火时即从炮体扣除；② 填充方块放置量 ≤ 消耗量（**1:1，绝不增殖**）；③ 爆炸破坏的方块默认不掉落。

### 5.3 弹坑中心的安全性

落点若是水面/岩浆/虚空：石碑先找安全落点（向上找 3 格空间），找不到就作为物品掉落。

## 6. 与「传送石碑」的联动（已核实 API）

Waystones 14.1.21 的公开 API 足够，不需要 mixin：

```java
// 1) 落地放碑（返回的 IWaystone 已注册进存档）
Optional<IWaystone> ws = WaystonesAPI.placeWaystone(level, pos, WaystoneStyles.DEFAULT);
// 2) 为发射者激活（placeWaystone 只负责放置与注册，激活需要显式调用）
ws.ifPresent(w -> PlayerWaystoneManager.activateWaystone(shooter, w));
// 3) 可选：全服可见
// PlayerWaystoneManager.activeWaystoneForEveryone(server, w);
```

- 也可反过来：**瞄准已有石碑**，用 `getActivatedWaystones(player)` 做目标列表。
- 传送本身用 `forceTeleportToWaystone`（无视消耗）或 `createDefaultTeleportContext` + `tryTeleport`（走正常消耗）。
- 若要做「炮击把玩家送到石碑」，可直接复用 `IWaystone#resolveDestination(ServerLevel)` 得到精确落点。

## 7. 地图联动（S6）

**已确认：JourneyMap（旅行地图）**。它提供 `journeymap-api`，可以写路点、画 overlay。

| 候选 | 常见中文名 | 可用的集成方式 |
| --- | --- | --- |
| **JourneyMap ✅** | 旅行地图 | `journeymap-api`，可加 overlay / 路点 |
| Xaero's Minimap + World Map | Xaero 小地图 / 世界地图 | 官方 API 较弱，主要能写路点 |
| FTB Chunks | FTB 区块 | 团队/领地相关，不适合画轨迹 |

M5 方案：**落点自动生成一个 JourneyMap 路点**（带图标与距离），外加瞄准时的**客户端弹道预览线**。
JourneyMap 不是硬依赖——没装就退回「可点击坐标」。

## 8. 多人兼容（S7）

原则：**服务端权威，客户端只做表现**。

- 瞄准/装填/点火全部走服务端校验（玩家在炮位、有权限、冷却、负载匹配）。
- 炮弹是服务端实体，客户端通过实体追踪看到；关键参数用 `SynchedEntityData` 同步。
- 弹道预览由客户端用**相同公式**本地计算（不占服务端带宽），服务端只在点火时复算一次防作弊。
- 区块 ticket 只在服务端；玩家负载时天然有玩家 ticket，不需要额外加载。
- 并发/防滥用：每炮一门冷却、每人同时 1 发、全服上限可配。

## 10. 已确认的设计决策

## 11. 踩坑记录（给后续开发）

1. **实体 tick 不可靠**：0 人服务器上 vanilla 盔甲架都不下落，靠 `Entity#tick()` 驱动的炮弹会冻住。
2. **实体所在区块卸载 → 炮弹永久冻结**：实体被区块卸载带走并写进存档，玩家飞过去只看到一个悬在半空的壳。
   最终架构：**飞行状态由 `ShellManager` 在服务端内存持有，实体只是可抛弃的视觉载体**——
   载体没了就在当前位置重新生成一个，飞行照常继续（`/cannon debug` 能看到「载体:有/无」）。
   实测：飞行途中 `/kill` 掉实体，3 秒后载体自动重建，5km 飞行照常落点。
3. **迭代中回调删元素**：命中时 `discard()` → 回调改列表，整服 CME。
4. **Balm/Waystones 的 Mixin 在 dev 环境需要 `mixin.env.remapRefMap`**（见 build.gradle）。
5. **调试命令的坐标语义**：`testfire 400 ~ ~` 里的 400 是绝对 X 而不是距离，会让人误以为「落点都一样」。
   已改成 `testfire <距离>` + `testfire at <x y z>`。
